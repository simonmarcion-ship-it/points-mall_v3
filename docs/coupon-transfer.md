# 优惠券转移

适用于新旧手机号均已建档、两个账号下都有同一车辆，导致“转移车辆”被重复车辆校验拦截的情况。

管理员或超级管理员操作：

1. 查询旧手机号，进入客户详情。
2. 选中一张未使用券，点击券详情中的“转移优惠券”，也可右键该券选择该操作。
3. 输入目标手机号。系统匹配目标账号已有的同 VIN 或同车牌车辆。
4. 核对新旧客户、车辆、券码和有效期，确认后填写转移原因。
5. 每张券单独转移。目标客户刷新个人中心后，可在已有车辆下查看该券。

转移后原账号不再显示该券；券码、有效期、使用范围及其他原始券信息保持不变，账号认证和车辆记录保持原状。每次操作只转移选中的一张券，并记录操作人、原因和双方客户及车辆信息。

已使用、已作废、已过期的券不能转移。目标手机号对应多个有效客户、匹配到多辆车辆或有效 VIN 冲突时也会拦截。正式转移时重新检查归属和状态；转移和日志在同一事务内提交，失败则回滚。

## 部署

本功能无需新增数据库迁移。代码推送后，在服务器项目目录更新并重建后台：

```bash
cd /root/points_mall/points-mall_v3
git pull --ff-only
docker compose --env-file deploy/.env -f deploy/docker-compose.yml up -d --build --force-recreate admin
```

更新后刷新后台，以加载新权限和页面资源。

## 验证

回归检查使用临时数据库，不访问业务数据库。安装项目依赖和 `httpx` 后，在项目根目录运行：

```powershell
python -m unittest discover -s tests -p test_coupon_transfer.py -v
node --check admin/web/frontend/app.js
```

检查覆盖转移后的真实客户端可见性、保留券资料、权限、无效券、重复提交、预览后的状态变化、车辆匹配冲突和日志写入失败回滚。
